# 弹窗抽屉与页面

## 适用条件

为编辑、详情或新的业务流程选择容器。

## 排除条件

本次任务没有改变信息结构或容器时不重做选型。

## 规则

先确认任务是否独立、是否需要与背景交互、是否连续处理条目，以及内容与导航深度；不只按字数和容器宽度判断。

| 任务条件 | 候选与取舍 |
| --- | --- |
| 小范围修改，当前页面有足够空间且无需中断其他操作 | 优先复用行内编辑或现有详情区，不必新增容器 |
| 短而独立，确需暂时集中完成的子任务 | 考虑弹窗；需要编辑输入时补查 UXR-0018、UXR-0027 |
| 连续处理列表条目，需要保留滚动、筛选和选择 | 考虑抽屉；关闭或切换条目时保留上下文并检查未保存修改 |
| 编辑时还必须操作背景内容 | 评估非模态抽屉或页面内分区；看得到背景不等于可以操作背景 |
| 长表单、深层导航或可独立返回的流程 | 考虑页面；返回时恢复必要列表状态，窄屏不能只缩窄桌面弹窗 |

抽屉是否模态单独决定，并按 UXR-0029 处理焦点与背景交互。表中的条件是工程判断起点；现有组件能满足任务时优先复用，不强制迁移容器。

## 参数

400/520/720px 是弹窗桌面候选，不按字符数机械切换；移动端可切换全屏。

## 验收

以最短和最长数据验证；编辑完成后能按预期处理下一条；返回列表不丢上下文。

例如只改列表名称时比较行内编辑；连续审核多条记录时检查抽屉的下一条、未保存保护和焦点；独立多步骤流程验证页面返回路径。分别说明选中方案满足什么条件，以及至少一个替代方案为何不适用。

## 反例

长流程全部塞进 400px 弹窗，或者为了对照选择模态抽屉却仍允许点击背景。
