# 选择输入与命令菜单选型

## 适用条件

为值选择、筛选、选项比较或一组操作选择控件。

## 排除条件

本次仅调整样式且现有语义与交互正确时；选项数变化本身不要求重做组件。

## 规则

选择或修改一个值时考虑 Select、Radio 等输入控件；执行命令或导航时考虑按钮或命令菜单。即时生效与等待提交是项目策略，边框有无是外观，都不能用来定义控件类型。无边框 Select 仍需可感知的名称、当前值及正确的展开状态；危险菜单动作另按 UXR-0019 或 UXR-0024 判断恢复与确认。

| 当前条件 | 判断起点与例外 |
| --- | --- |
| 少量短选项，需要比较且有空间 | 优先评估可见选项；两项不自动等于开关，Switch 只适合有明确开/关含义的状态 |
| 工具栏空间紧，或少数选项包含较长说明 | 比较 Select、纵向单选等方案；不因少于五项就强制横向平铺 |
| 选项多且用户可用名称检索 | 考虑搜索、分组或原生键盘定位；熟悉且固定的十二个月不因超过十项就必须加搜索 |
| 用户熟知要输入的日期或电话 | 评估直接输入；生日与预约可用日期的限制不同，电话不是从任意号码列表选择 |

优先复用原生或已验证组件，检查名称、值、展开/关闭、键盘选择与焦点。面板位置按可用视口、缩放、软键盘和内容避让，不把触发器位置当成固定动画方向；空间不足时改变布局仍需保留可操作内容。

## 参数

选项数用于提示评估，不能单独决定控件。5 项、10 项来自特定设计系统的建议；264px 没有通用依据。面板上限采用项目与视口约束，搜索的收益还取决于选项长度、熟悉度和查找方式。

来源分别支持组件语义、开关状态及特定场景建议，不证明本表适合所有产品，也不规定所有 Select 必须带框或等提交。

## 验收

对照两项排序、三个长方案、十二个月份和长搜索列表分别说明选择理由。检查无边框控件的名称与当前值、键盘取消与选择、窄屏及软键盘下的面板操作；不得只凭截图判断语义正确。

## 反例

把“按名称/按时间”改成无清楚开关含义的 Switch；把三个长方案硬挤在一行；因为十二个月超过十项就强加搜索；仅靠边框区分删除命令和选择值。
