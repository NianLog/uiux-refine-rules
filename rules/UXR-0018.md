# 未保存输入保护

## 适用条件

弹窗、抽屉或页面中存在用户尚未提交的修改。

## 排除条件

只读详情、未修改状态，以及当前输入版本已有明确自动保存成功回执的状态；旧版本保存成功不能排除较新修改。

## 规则

关闭按钮、Escape、遮罩、切换条目和应用内导航进入同一退出判断，遮罩点击不得静默丢弃输入。区分“请求退出”和“实际丢弃”：有未保存修改时可取消退出、明确放弃，或使用已经验证的草稿恢复；不要为了保护输入永久取消退出路径。

| 当前状态 | 退出与反馈 |
| --- | --- |
| 未修改，或当前版本已确认保存 | 按组件约定退出，不增加无意义的丢弃确认 |
| 有未保存修改 | 保留输入；先让用户选择继续编辑或明确放弃。只有恢复能力真实成立时才提供保存草稿退出 |
| 保存中 | 防止重复提交并说明进度；离开是否安全取决于请求能否继续、草稿和结果入口，不能把关闭界面当作取消保存 |
| 明确保存失败 | 保留输入及失败说明；按实际失败原因提供修正或重试，不显示已保存 |
| 结果未知 | 保留输入并核对已有请求结果；未经核对不按失败自动重复提交 |

保存回执必须对应提交时的输入版本。保存 A 的响应晚于用户的新修改 B 时，不能把 B 标为已保存。草稿需定义失败提示、敏感字段排除、恢复时机和保存范围；不能未经支持就声称自动保存。

## 参数

关闭规则按未修改、dirty、saving、saved、error 和结果未知分别定义；自动保存不是所有表单的必选项。应用内退出保护不能证明浏览器关闭或崩溃后仍可恢复，这些路径须单独验证。

状态表属于工程约束。GOV.UK 来源支持校验失败时保留用户输入；其政府服务流程中的校验时机不作为所有应用的通用要求。

## 验收

填入内容后逐一走退出路径；模拟保存失败和结果未知，输入仍可恢复且不会显示假成功。

至少核对未修改直接退出、有修改取消退出、放弃后退出，以及 A 保存中继续输入 B 的迟到回执；保存失败后输入不清空。存在草稿时另验实际恢复内容，缺少草稿能力时不展示相应承诺。

## 反例

禁用遮罩关闭却允许 Escape 直接丢弃，或把敏感表单完整写入 localStorage。
