# 浮层选型

## 适用条件

需要决定是否增加反馈，或在 Tooltip、Toast、Alert、Modal 和 Popconfirm 之间选择。

## 排除条件

已有组件实现且本次仅调整局部样式时不重新选型。

## 规则

先确认用户当前任务、结果是否已确定、信息能否再次找到、是否必须回应，以及重复出现的频率。不要把组件排成固定打扰等级，也不要因为操作发生了就新增提示。

| 当前条件 | 优先考虑 | 继续读取与边界 |
| --- | --- | --- |
| 控件或页面已有清楚、可访问的结果反馈，无额外决策 | 保留现有反馈或就地更新状态 | 不再叠加重复 Toast；确认用户仍能获知失败和完成状态 |
| 已有名称的控件需要非关键补充说明 | Tooltip | UXR-0012；关键说明、交互内容或触屏唯一入口不适用 |
| 已确认的短结果可在其他位置再次确认 | Toast | UXR-0013；若现有状态已足够，可不增加 Toast |
| 状态持续影响页面或局部任务 | 对应区域的 Alert | UXR-0014；字段错误读 UXR-0027，不用全局通知替代字段定位 |
| 用户必须回应后才能继续当前任务 | Modal | UXR-0015；重要不可逆动作另读 UXR-0024 |
| 局部操作确实需要简短确认，且损失说明不复杂 | Popconfirm | UXR-0016；能可靠撤销时先按 UXR-0019 判断，高频本身不是理由 |

选择后只读取实际相关的组件规则。信息未确认时表达等待或结果未知，不能先报成功；有动作的反馈还需检查可操作期限和关闭后的入口。

## 参数

每次只选满足任务的最轻交互；Modal 不局限于二选一，Popconfirm 不因高频就自动适用。

选型表是工程建议。所列 WCAG 说明支持状态消息的可访问表达，不规定必须使用 Toast，也不证明上述选型已适合某个项目。

## 验收

用实际任务解释选择理由，并列出关闭、超时、键盘和失败行为。

- 自动保存已在编辑器内显示对应版本的保存状态：核对反馈可被感知后，允许不追加 Toast。
- 持续网络故障阻止保存：在相关区域保留失败及恢复入口，不能只闪过一条成功样式提示。
- 只调整现有组件颜色：不借此重做容器或增加确认步骤。

## 反例

重要错误只显示两秒 Toast，或者所有删除都固定套用 Popconfirm。
